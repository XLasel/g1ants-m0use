# Как мы работаем с репозиторием

## Ветки

Сроки короткие, поэтому ветки простые: `main` и ветки задач.

| Ветка | Зачем |
|---|---|
| `main` | Общая рабочая ветка, из неё собирается APK для сдачи. Всегда должна собираться. |
| `task-<N>-<тема>` | Работа по задаче. Отводится от свежего `main`, возвращается в `main` через pull request. |

Перед pull request подтяните свежий `main` в свою ветку и проверьте сборку.

Номера задач закреплены за ролями:

| Задача | Роль | Пример ветки |
|---|---|---|
| 1 | Приложение и интерфейс | `task-1-app`, `task-1-recording` |
| 2 | Речь и звук | `task-2-speech-recognition` |
| 3 | Диаризация | `task-3-diarization` |
| 4 | Локальная LLM, качество, документы | `task-4-local-summary`, `task-4-quality-tools` |

Тема в имени ветки — латиницей, через дефис.

## Коммиты

Формат [Conventional Commits](https://www.conventionalcommits.org/ru/): `тип(область): что сделано`.

- **Типы:** `feat`, `fix`, `refactor`, `test`, `docs`, `build`, `chore`, `perf`.
- **Область** — модуль или часть приложения: `speech`, `diarization`, `summary`, `pipeline`, `app`, `ui`, `android`, `docs`.
- **Описание** по-английски, с маленькой буквы, в повелительном наклонении (`add`, `fix`, `move`), без точки в конце.
- Один коммит — одно законченное изменение.

```
feat(speech): add loudness envelope and chunked word output
fix(android): package arm64 only to avoid duplicate libonnxruntime.so
docs(diarization): describe threshold tuning
```

## Pull request

- Из `task-*` в `main`. Название — как у коммита.
- В описании: что сделано, как проверить, что осталось.
- Перед слиянием: проект собирается, тесты модуля проходят.

## Код

- Kotlin, официальный стиль Kotlin (`ktlint`/форматирование Android Studio по умолчанию).
- Имена классов, функций и переменных — по-английски.
- Комментарии и KDoc — по-русски. Пишем их для человека, который впервые открыл файл: что здесь происходит и зачем. Не комментируем каждое действие и очевидный код. У публичных классов и функций есть короткий KDoc.
- Время везде в миллисекундах (`Long`), звук — `FloatArray` 16 кГц моно.
- Спикеры в данных — `speaker_1`, `speaker_2`… в порядке первого появления.
- Без закомментированного кода и отладочных `println`.
- Логику, которую можно проверить без телефона, покрываем модульными тестами.

## Модели и большие файлы

Модели и APK в git не кладём (лимит GitHub 100 МБ на файл). Модели скачиваются скриптами из `src/android/scripts`, APK выкладывается в Releases.
